# hsmcpp Requirements Terminology

This document defines terms used throughout the system and software requirements.

## State Machine Lifecycle

**Initialization**: The operation that transitions a configured state machine from the configuration phase into an executing state. After initialization, the initial state is active and events can be processed.

**Release**: The operation that terminates execution and returns the state machine to a configurable state. After release, the state machine does not process events until re-initialized.

**Active state configuration**: The set of states that are currently active in a state machine at any point during execution. In a flat state machine this is a single state; with hierarchy it includes the active state at each level; with parallel regions it includes the active state in each region.

## Events

**Event**: A uniquely identified stimulus that can trigger state transitions.

**Externally submitted event**: An event submitted by application code through the library's event submission interface.

**Internally generated event**: An event generated by the library itself during processing, including events from declarative actions (automatic event generation), final state completion events, and timer expiration events.

## Transitions

**Transition request**: A request submitted to the state machine to process a specified event, potentially causing a state change.

**Transition**: The process of changing the active state configuration in response to an event, including execution of associated callbacks.

**Successful transition**: A transition that completes the full callback sequence without cancellation, resulting in the target state becoming active.

**Cancelled transition**: A transition that is terminated by a cancellable callback (exit or entry) before the target state becomes active. The active state configuration is restored to its pre-transition state.

**Failed transition**: A transition request that cannot be processed because no matching transition exists for the event in the current active state configuration, or because all matching transitions have unsatisfied guard conditions.

## Callbacks

**Cancellable callback**: A callback that can terminate the transition in progress by returning a cancellation indication. Exit callbacks and entry callbacks are cancellable.

**Non-cancellable callback**: A callback that cannot terminate the transition. State-changed callbacks and transition callbacks are non-cancellable.

## Timers

**Timer expiration event**: An internally generated event produced when a timer's configured interval elapses.

**Single-shot timer**: A timer that generates one expiration event and then stops automatically.

**Repeating timer**: A timer that generates periodic expiration events at a configured interval until explicitly stopped.
